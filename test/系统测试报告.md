#### 3.4.2 并发容量基线

**测试条件**：单实例部署 / HikariCP 连接池 10 / 本机 localhost / 每接口 300 请求 / 多线程并发发起。

| 接口 | 并发 | QPS | P50 | P95 | P99 | 错误数 |
|------|:---:|---:|---:|---:|---:|:---:|
| POST /auth/login | 10 | 139.3 | 67.4 ms | 88.5 ms | 92.9 ms | 0 |
| GET /books?page=1&size=10 | 10 | 483.6 | 13.1 ms | 32.8 ms | 181.2 ms | 0 |
| GET /borrow-records?page=1&size=10 | 10 | 637.5 | 11.6 ms | 29.8 ms | 33.2 ms | 0 |
| GET /stats/overview | 10 | 851.6 | 9.9 ms | 26.2 ms | 29.0 ms | 0 |
| POST /auth/login | **50** | 178.9 | 238.5 ms | 392.4 ms | 498.5 ms | 0 |
| GET /books?page=1&size=10 | **50** | 1008.9 | 35.0 ms | 60.1 ms | 81.2 ms | 0 |
| GET /borrow-records?page=1&size=10 | **50** | 1138.2 | 31.6 ms | 52.3 ms | 62.4 ms | 0 |
| GET /stats/overview | **50** | 1219.1 | 30.2 ms | 65.1 ms | 74.2 ms | 0 |

**共 2400 次请求，错误 0**。

**结论与分析**：
1. **读接口在并发 50 下仍保持 1000–1200 QPS、P95 ≤ 66ms**，连接池容量（10）未成为瓶颈；即使在最坏情况下（登录 P99 498.5ms）**仍满足 ≤500ms 的需求指标**。
2. **瓶颈定位为登录路径的 BCrypt 校验**（密码哈希为 CPU 密集型，单次约 60–80ms）：登录 P50 由 67.4ms（并发 10）升至 238.5ms（并发 50），QPS 仅为读接口的 1/6~1/7。该开销属**安全特性**（慢哈希用于抗暴力破解），若需更高登录吞吐可将 BCrypt strength 由 10 降至 8（预计提升约 3–4 倍，仍属强哈希）。
3. `/books` 在并发 10 时 P99 出现 181.2ms 毛刺（P50 仅 13.1ms），属首次连接/JIT 预热的一次性现象。
4. **容量估算**：按本机数据折算生产环境（扣除网络与折损），单实例读接口约可支撑 350–400 QPS、登录约 180 QPS，**足以覆盖中小型图书馆规模**（日活千级、峰值数百并发）。

### 5.5 弹窗引起整页右移的专项修复（2026-09-15）

**现象**：打开任一二/三级界面弹窗后，整页元素（含卡片右边框）向右平移约 15px。

**根因**：`body` 未重置 margin（浏览器默认 8px）+ `.layout-root { height: 100vh }` → 文档比视口高 16px，页面长期挂着一条竖向滚动条；Element Plus 打开弹窗时给 `body` 加 `overflow: hidden` 锁背景滚动，**滚动条一消失、内容区就宽出约 15px**，于是整页右移。顺带影响：因该溢出，页面可向下滚 16px，应用最底部 8px 被挡在可视区外。

**修复**（3 处纯 CSS）：`body { margin: 0 }` + 顶栏与内容区内边距各 +8px 配套，**界面铺满窗口且文字/卡片位置与改动前完全一致**。

> 方法学提示：无头 Chromium 默认隐藏滚动条，此类问题**默认无头环境下复现不出（假阴性）**，需 `ignoreDefaultArgs: ['--hide-scrollbars']` 启动。
