# 巡检规则万级性能实测（2026-10-20）

> 脚本：`test/perf/bench_audit_rules.py`；探针库 `library_all14`（跑完自动 DROP）。
> 规模：book=10,000 / borrow=50,000 / fine=25,000。
> 口径：逐条规则 SQL 的实际耗时（同一进程内连续执行），**不是** `/audit/run` 端到端时延。

- **串行合计**：第 1 次 ≈ 1,081 ms / 第 2 次 ≈ 1,059 ms，取小 **≈ 1.06 s**
- **最慢单条**：R1 = 134 ms（两次分别为 134 / 141）

## 与论文旧值的关系

论文 6.2.2 原写「最慢 103 ms、串行合计约 1.04 s」，该值出自 2026-10-14 的手抄表（每规则取 2 次最小值）。
本次复测：合计基本一致（1.04 → 1.06 s，仍在「约 1 秒」量级），但**单条最慢由 103 ms 上升到 134 ms**（机器负载与缓存状态差异）。
**结论口径不变**：万级数据下巡检逐条 SQL 合计约 1 秒，远低于接口 500 ms 指标的讨论范畴（不同口径，勿混用）。
