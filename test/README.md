# test/ ——LibMS 审查工具集（使用说明）

> 本目录是项目的**完整审查工具链**：单一运行器 + 分层测试套件 + 共享库。
> 设计原则：**正确合理、适合本项目、审查全面**（允许为有效性重构；判定 = 退出码 0 **且** 通过数 == 注册期望数，报告自动落盘并带代码指纹）。

---

## 1. 快速开始（三步）

```bash
# ① 起环境（两个长驻进程；凭据见《从零开始运行手册》）
java -jar backend/target/libms-backend-1.0.0.jar --server.port=8080   # 后端
cd frontend && npm run dev                                             # 前端（仅浏览器套件需要）

# ② 一条命令跑完全部审查（运行器自动：预检 → 逐套件重置种子 → 执行 → 汇总）
python test/run_all.py --browser

# ③ 查看结果：控制台汇总 + 报告文件 test/artifacts/audit_YYYYMMDD_HHMMSS.md
```

运行器退出码：`0` 全绿 / `1` 有套件失败 / `2` 环境未就绪（预检不过，看提示）。

**不再需要人工逐脚本重置种子**——运行器在每个套件前自动重置（`docs/04_数据库设计.sql`），
这是历史"顺序污染导致静默缩量"问题的根治方案。

> ⚠️ **注意**：`reset_seed()` 会 **DROP/重建 `library_db`**（`test/_common.py:101-102`），**不是隔离临时库**；运行全量回归前先备份非种子数据。

## 4. run_all 用法

```bash
python test/run_all.py                  # 全部后端套件
python test/run_all.py --browser        # 追加浏览器套件（需 5173 + node + playwright）
python test/run_all.py --suite smoke_test   # 只跑单个套件（调试用）
python test/run_all.py --list           # 查看套件清单与期望项数
```

> 运行器纯标准库实现，**不依赖 shell 管道与 coreutils**；所有外部程序（mysql/python/node）
> 按"命令名 → 本机安装路径"双候选探测（见 `_common.py`）。

## 5. 环境要求与常见问题

| 依赖 | 用途 | 缺失时 |
|---|---|---|
| MySQL 8.0 客户端 | 种子重置 + DB 断言 | 预检拦截；DB 断言类脚本内部优雅 SKIP |
| 后端 8080 | 全部接口类套件 | 预检拦截（给出启动命令提示） |
| 前端 5173 + node + playwright | 仅 `--browser` | 跳过浏览器套件并提示 |
| `LIBMS_DB_PWD` 环境变量 | 覆盖默认测试口令 | 默认 `123456`（本地测试口径） |

**常见问题**
- 某套件报 `[BASELINE FAIL]`：运行器会自动重置种子，正常不应出现；若手动单跑脚本，须先自行重置（`mysql … < docs/04_数据库设计.sql`）。
- 浏览器套件找不到 playwright：优先使用 `test/browser/node_modules`（playwright@1.62 已固化；`%TEMP%\pwcheck` 为历史路径）；也可在 `test/browser/` 下 `npm i playwright`。
- 本机 npm shim 被安全策略拦截时，用 node 直跑 vite/eslint（构建验证不受影响）。

## 6. 扩展指南（新增套件三步）

1. **写脚本**：放 `test/` 下，推荐基于 `_common.py`（`import _common as C`）复用探活/重置/直查；
   脚本须遵守三条约定：**独立可跑**（自带基线检查）、**失败退出码非 0**、**净零副作用**（自建数据自清理）。
2. **注册**：在 `run_all.py` 的 `BACKEND_SUITES`/`BROWSER_SUITES` 加一行 `(名称, 路径, 类型, 期望项数)`。
3. **登记**：更新本 README 的套件清单与 `test/系统测试报告.md` 的基线数字。

## 7. 设计原则备忘（与项目三类对象原则配套）

- **审查工具**：正确合理、适合本项目、审查全面——**允许重构与重新设计**，判定 = 退出码 0 且 通过数 == 注册期望数（2026-10-24 加固；期望不符不再只写备注，见 §3 末"判定口径"）。
- **测试数据**：种子日期一律用 `CURDATE()±N` 相对表达（防时间漂移）；断言前先探测真实行为（防假失败）。
- **判据纪律**：断言走"精确码 + 语义条件"（拒绝恒真/宽容/空集合恒真）；DB 类断言以账实一致为准。
- **DB 断言口径（第二十一轮沉淀）**：涉及逻辑删除表的"清理核对/计数"断言**必须显式加 `deleted=0`**——删除接口为逻辑删除、行仍在表内；security_test 4.1 曾因漏此条件出现"删除成功但计数恒为 1"的假失败，排查链：DELETE 200 → 直查残留 → 发现 deleted=1 行被计入。
- **调试可见性**：套件内临时调试打印会被运行器的 tail 截断——定位套件问题时直接 `python test/<suite>.py` 单跑查看完整输出。
