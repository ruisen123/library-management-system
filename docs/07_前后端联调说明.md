> 📌 **关于 `deleteUser` 的设计说明（2026-09-11 补充）**：删除用户为 **API 级能力**——后端端点存在且带三重护栏（禁止自删除、有在借记录禁删、有未缴罚金禁删），前端 `api/user.js` 亦保留其封装；但**管理界面按 `docs/03` 的用例清单以「冻结/启用」替代删除**（冻结可逆、删除不可逆，管理侧诉求是"停用"而非"删除"），故 `UserManage` 页面不提供删除入口。该函数当前仅供自动化测试（`smoke_test*` / `e2e_full_flow`）与接口级调用使用；如后续需要在界面提供入口，可在操作列补充按钮并复用既有二次确认模式。

> 请求方法、URL 路径、参数命名、返回结构（`Result{code,msg,data}` + 分页 `{records,total}`）三方一致。
> 业务状态码：`200` 成功 / `400` 参数校验失败（含超长/越界字段、**必填参数缺失**）/ `401` 未登录或令牌失效 / `403` 无权限 / `404` 资源不存在 / `405` 请求方法不支持 / `500` 业务规则未通过（如库存不足、状态不允许）。
> 分页参数约定：`page`/`size` 后端默认 1/10，并在 Controller 入口归一化（`page`、`size` 下界强制为 1，`size` 上界由 `PaginationInnerInterceptor.maxLimit=1000` 保障），防止非法分页参数绕过物理分页返回全表。

## 四、配置变更说明（本次联调）

1. **关闭 Mock**：`frontend/.env.development` 与 `.env.production` 中 `VITE_USE_MOCK=false`，前端所有请求改走真实 HTTP；
2. **接口基础路径**：`utils/request.js` 的 `baseURL` 改为 `import.meta.env.VITE_API_BASE || '/api'`，默认 `/api` 经 vite 代理指向 `http://localhost:8080`；如需直连可改 `VITE_API_BASE` 为完整地址（后端已开 CORS）；
3. **后端不提交真实口令**：`application.yml` 中 `DB_PASSWORD` / `JWT_SECRET` **不提供默认值**（缺失即启动失败，fail-fast），必须通过环境变量显式设置；本地开发请在 IDEA Run Configuration 或 shell 中配置 `DB_PASSWORD` / `JWT_SECRET`。
4. **Vite 监听地址**：`vite.config.js` 当前设置 `host: '127.0.0.1'`（仅本机回环，开发服务器不暴露局域网；如需联调临时改 `0.0.0.0` 并在结束后还原）。
5. **注册限流与预约回收（2026-10-22）**：`application.yml` 新增 `APP_REGISTER_MAX_PER_IP`（默认 5）、`APP_REGISTER_WINDOW_MINUTES`（默认 60）、`APP_REGISTER_GLOBAL_MAX`（默认 200）、`APP_RESERVATION_EXPIRE_SCAN_MS`（默认 300000）与 `APP_RESERVATION_EXPIRE_DELAY_MS`（默认 60000）；均为进程内单实例口径，多实例部署需改为共享计数。

> 关闭 Mock 后，`utils/mock.js` 不会进入构建产物：`request.js:42-49` 仅在 `VITE_USE_MOCK=true` 时挂载 mock adapter，且 mock 模块以 `await import('./mock')` **动态引入**，非 mock 构建下该分支被静态剔除（实测 `frontend/dist` 内 grep `mockAdapter` 0 命中）；`VITE_USE_MOCK=false` 时 mock 数据不参与任何请求，页面数据全部来自真实后端接口，前端不存在硬编码业务数据。

## 六、常见联调问题排查指南

### 6.1 跨域问题（CORS）
- **现象**：浏览器控制台报 `Access-Control-Allow-Origin` 错误。
- **原因**：前端直连后端（未走 vite 代理）时浏览器同源策略拦截。
- **排查**：① 确认前端走 `/api` + vite 代理（推荐，开发期无跨域）；② 若直连，确认后端 `CorsConfig` 已生效。

### 6.2 401 未授权
- **现象**：接口返回 `code=401` 或拦截器提示「请先登录」。
- **原因**：请求头未携带 token、token 过期、token 无效。
- **排查**：① 确认请求头名称为 `token`（`jwt.header` 配置）；② 检查 localStorage 是否有 token；③ token 过期（默认 24h）需重新登录；④ 确认数据库用户 `deleted=0`。

### 6.3 参数格式不匹配
- **现象**：返回 `code=400` 参数错误，或字段为 null。
- **原因**：前后端字段命名/类型不一致。
- **排查**：① JSON 字段命名：前端小驼峰 ↔ 后端实体属性小驼峰（MP 已配下划线映射）；② 请求体需 `Content-Type: application/json`；③ 分页参数用 `page`/`size`（后端 `@RequestParam` 默认值 1/10，并在 Controller 入口归一化下界为 1）。

### 6.4 日期格式不一致
- **现象**：前端收到 `2026-01-01T09:00:00`（带 `T`）。
- **原因**：未配置 LocalDateTime 序列化格式。
- **排查**：确认后端 `JacksonConfig` 已生效；前端无需处理，直接展示。

### 6.5 连接失败 / 网络异常
- **现象**：前端提示「网络异常，请检查后端是否启动」。
- **排查**：① 后端是否启动（8080 端口）；② MySQL 是否启动、`library_db` 是否已建；③ 数据库账号密码环境变量是否配置正确。
