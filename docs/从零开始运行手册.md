# LibMS 图书借阅管理系统 · 从零开始运行手册

> **适用对象**：完全没有接触过 Java / Vue 的同学（0 基础）
> **操作系统**：Windows 11
> **最终目标**：把「数据库 → 后端 → 前端」三个程序依次启动，用浏览器打开系统并成功登录
> **本手册说明**：全文命令与结果**均已在本机实际跑通验证**，可放心照抄

---

## 开始之前：先搞懂 3 件事

这个系统不是一个程序，而是**三个程序配合工作**，必须**按顺序**启动：

| 顺序 | 程序 | 作用 | 打个比方 |
|:---:|------|------|----------|
| ① | **MySQL 数据库** | 存放所有数据（用户、图书、借阅记录…） | 仓库 |
| ② | **后端 Spring Boot** | 处理业务逻辑、提供数据接口（端口 8080） | 后厨 |
| ③ | **前端 Vue** | 你在浏览器里看到的网页界面（端口 5173） | 餐厅大堂 |

**一句话流程**：

```
开数据库  →  开后端(8080)  →  开前端(5173)  →  浏览器登录
   ↑             ↑                 ↑
 存数据      提供接口            展示页面
```

> ⚠️ **顺序不能乱**：后端要连数据库，前端要连后端。数据库没开，后端就起不来；后端没起，前端打开也是白屏/报错。

**本项目在你电脑上的位置**（后文所有命令都基于这个路径）：

```
C:\Users\<你的用户名>\Desktop\软件\SpringBoot Vue library
```

> 如果你把项目复制到了别的地方，把命令里的路径换成你自己的即可。

## 第 3 章　启动数据库（第一步）

### 3.1 确保 MySQL 服务在运行

数据库软件装好后是作为一个「后台服务」运行的。检查方法：

**方法一（图形界面，推荐新手）**：
1. 按 **Win + R**，输入 `services.msc`，回车；
2. 在弹出的列表里找到名为 **MySQL** 的服务（可能叫 `MySQL` 或 `MySQL80`）；
3. 看「状态」列，如果是「正在运行」就 ✅ 不用管；
4. 如果不是，右键 → 「启动」。

**方法二（命令行，需管理员权限）**：

```bat
net start MySQL
```

出现「MySQL 服务已经启动成功」或「服务已经启动」都算成功。

### 3.2 导入数据库脚本（第一次运行时必须做）

> 📌 **重要：项目交付时数据库是空的**（没有任何业务数据），所以**第一次运行前必须执行本步**——它会创建 `library_db` 数据库、10 张表，并灌入一套**演示数据**（6 个用户 / 6 本图书 / 借阅与罚金记录等）；后面第 6 章要登录的账号，就来自这里。脚本可以重复执行（每次都会先清空再重建，不会出错）。

这一步会把 `library_db` 数据库、10 张表、以及所有测试数据一次性创建好（`reservation` 预约表、`notification` 站内通知表为 2026-10-22 扩展新增，种子默认空，不影响演示数据）。

打开命令提示符，**先进入项目目录**，再执行导入：

```bat
cd /d "C:\Users\<你的用户名>\Desktop\软件\SpringBoot Vue library"

mysql -u root -p123456 --default-character-set=utf8mb4 < docs\04_数据库设计.sql
```

> ⚠️ **两个关键点，缺一不可**：
> 1. `-p` 和密码之间**不要加空格**（写成 `-p123456`）；
> 2. **必须加 `--default-character-set=utf8mb4`**，否则导入中文数据时会报 `ERROR 1406: Data too long`。

**实测情况**：执行后脚本会自己打印一段核对结果（表名/行数、借阅示例、库存核对），最后回到光标。**这就是成功**，不用担心。

### 3.3 验证数据库是否建好

再执行下面这条命令查询一下：

```bat
mysql -u root -p123456 --default-character-set=utf8mb4 -e "USE library_db; SHOW TABLES; SELECT COUNT(*) AS 用户数 FROM sys_user;"
```

**预期结果**：先列出 **10 张表**，最后显示 **用户数 = 6**。

```
Tables_in_library_db      ← 10 张表
book
borrow_record
category
fine_record
notice
operation_log
publisher
reservation
sys_user
用户数
6                         ← 6 个用户
```

✅ 看到 10 张表和数字 6，说明数据库这一步彻底完成。

## 第 4 章　启动后端（第二步）

后端是「后厨」，启动方式有 **两种**，**新手推荐方式 A**（最省事）。

> 💡 无论哪种方式，后端都**需要一个黑窗口一直开着**（关掉窗口=关掉后端）。所以请单独开一个命令提示符，不要和后面的前端共用。

### 方式 A：直接运行打包好的程序（推荐 ⭐，已实测）

项目里已经有一个打包好的后端程序 `backend\target\libms-backend-1.0.0.jar`，直接运行即可，**不需要 Maven**。

**第 1 步**：打开一个新的命令提示符，进入后端目录：

```bat
cd /d "C:\Users\<你的用户名>\Desktop\软件\SpringBoot Vue library\backend"
```

**第 2 步**：逐条输入下面 3 条命令（设置启动参数），**每输一条回车一次**：

> 💡 **想省事就别手输了**：项目根目录的 `一键启动.bat` 已内置这两条口令（`DB_PASSWORD` 与 `JWT_SECRET`）并会自动打开前后端，双击即可。本章的手动步骤用于理解原理、或在 bat 跑不通时排查。
> ⚠️ 若你手动设了 `JWT_SECRET`，它与 bat 内置的不是同一个值——两边的登录令牌互不通用，换启动方式后需重新登录。

```bat
set DB_USERNAME=root
set DB_PASSWORD=123456
set JWT_SECRET=LibMS-2026-SecretKey-ChangeMe-0123456789abcdef
```

> - `DB_USERNAME`：数据库账号，默认就是 `root`；
> - `DB_PASSWORD`：MySQL 密码，本项目本机是 `123456`；
> - `JWT_SECRET`：登录令牌的加密密钥，**随便一串 32 位以上的字符**即可（上面这串只是示例，你可以自己改）。
> - `set` 命令只在**当前这个黑窗口**有效，所以必须和启动命令在同一个窗口里执行。

**第 3 步**：启动后端：

```bat
java -jar target\libms-backend-1.0.0.jar
```

**第 4 步：判断是否成功**。屏幕上会滚动大量日志，等几秒，看到下面这两行就成功了（实测约 4 秒启动完成）：

```
... Tomcat started on port 8080 (http) with context path ''
... Started LibraryApplication in 4.135 seconds (process running for 4.749)
```

> ❗ **这个黑窗口不要关闭**，关掉就等于关掉后端。放在那里别动，继续做第 5 章。

### 方式 B：用 Maven 从源代码启动（进阶，可选）

如果你以后**改了 Java 代码**，需要重新编译，就用这种方式。

```bat
cd /d "C:\Users\<你的用户名>\Desktop\软件\SpringBoot Vue library\backend"

set DB_USERNAME=root
set DB_PASSWORD=123456
set JWT_SECRET=LibMS-2026-SecretKey-ChangeMe-0123456789abcdef

mvn spring-boot:run
```

> 首次运行 Maven 会联网下载依赖，**可能要几分钟到十几分钟**，请耐心等待。
> 如果修改了代码想重新打包成 jar，用：`mvn clean package -DskipTests`，产物在 `backend\target\libms-backend-1.0.0.jar`。

### 第 4.X 步：验证后端是否真的活了

接口文档**默认关闭**（`APP_API_DOCS_ENABLED` 缺省 false，访问 `/doc.html` 返回 404）。如需在线调试，启动后端前先执行 `set APP_API_DOCS_ENABLED=true`，再打开：`http://localhost:8080/doc.html`

**实测结果**：显式开启后可正常打开接口文档页面（HTTP 200）✅，可在页面内在线调试接口；默认关闭时返回 404 属预期的安全行为。

也可以用命令行快速验证登录接口（**已实测**，返回 `code:200` 和一段 token）：

```bat
curl -X POST http://localhost:8080/auth/login -H "Content-Type: application/json" -d "{\"username\":\"admin\",\"password\":\"123456\"}"
```

预期返回：

```json
{"code":200,"msg":"登录成功","data":{"token":"eyJhbGciOiJIUzI1NiJ9...","user":{"id":1,"username":"admin","realName":"系统管理员","role":"ADMIN"}}}
```

## 第 7 章　每天怎么用（傻瓜式三步）

电脑重启后，不需要重新导入数据库（数据还在），只要按固定三步启动：

| 步骤 | 操作 | 说明 |
|:---:|------|------|
| ① | 确认 MySQL 在运行 | 一般开机自启；没启动就用 `net start MySQL` 或服务管理器启动 |
| ② | 启动后端 | 开黑窗口 → `cd 到 backend` → 设 3 个 `set` 变量 → `java -jar target\libms-backend-1.0.0.jar` |
| ③ | 启动前端 | 再开黑窗口 → `cd 到 frontend` → `npm run dev` |
| ④ | 打开浏览器 | 访问 http://localhost:5173 登录 |

**怎么关闭？**

- 后端 / 前端：在各自的黑窗口里按 **Ctrl + C**（或直接关闭窗口）；
- 数据库不用关（保持运行即可）。

## 第 8 章　常见问题排查

遇到问题先对照这张表找答案：

| 现象 | 原因 | 解决办法 |
|------|------|----------|
| 后端启动报错，提示 `DB_PASSWORD` 或 `JWT_SECRET` 为空 | 忘了设环境变量 | 确认在**同一个黑窗口**里先执行了 3 条 `set` 命令，再执行 `java -jar` |
| 后端报 `Access denied for user 'root'` | MySQL 密码写错了 | 检查 `set DB_PASSWORD=...` 里的密码是否正确（本机是 `123456`） |
| 后端报 `Communications link failure` | MySQL 没启动 | 用服务管理器启动 MySQL 服务 |
| 后端报 `Unknown database 'library_db'` | 数据库脚本没导入 | 回到第 3.2 步执行导入命令 |
| 导入 SQL 时报 `ERROR 1406: Data too long` | 字符集没指定 | 命令里加上 `--default-character-set=utf8mb4` |
| 前端页面能打开，但登录报「网络异常」 | 后端没启动 | 回到第 4 章启动后端，确认 8080 窗口在运行 |
| 登录提示「登录名或密码错误」 | 账号或密码输错 | 用第 6 章表格里的账号，密码统一 `123456` |
| 登录提示「账号已冻结，请联系管理员」 | 用了被冻结的账号 | 换成表格里正常的账号（`reader002` 是故意冻结的） |
| 接口返回「没有权限执行该操作」(403) | 当前角色无此权限 | 正常现象，见第 6 章小提示；换对应角色的账号即可 |
| 浏览器打不开 http://localhost:5173 | 前端没启动 | 确认 `npm run dev` 窗口在运行，且没有报错 |
| 提示 8080 端口被占用 | 之前启动的后端没关 | 关掉旧的后端窗口，或重启电脑后重新启动 |
| 前端 `npm run dev` 报模块找不到 | 依赖没装 | 执行一次 `npm install` 再 `npm run dev` |
| 中文显示成乱码 | 编码问题 | 确认 SQL 导入时加了 utf8mb4 参数；数据库已是 utf8mb4 字符集 |

### 万能排查顺序

出问题时，**按这个顺序反问自己**：

```
MySQL 开着吗？ → 后端 8080 窗口开着吗且没报错吗？ → 前端 5173 窗口开着吗？ → 账号密码对吗？
```

按「数据库 → 后端 → 前端」的顺序逐个确认，99% 的问题都能定位。

## 附录 D　原理小科普（可选阅读）

- **为什么前端访问 8080 却不写 8080？**
  前端配置了「代理」：凡是 `/api` 开头的请求，会自动转发到 `http://localhost:8080`。这样开发时就没有跨域问题，你也不用手动拼地址。

- **为什么密码是 `123456` 却能登录，数据库里却不是明文？**
  数据库里存的是加密后的密码（BCrypt 算法）。登录时程序把 `123456` 加密后去比对，一致就通过。这样即使数据库泄露，也看不到真实密码。

- **为什么改了 Java 代码要重新打包？**
  `java -jar` 运行的是已经打包好的 `.jar` 文件。改了源码必须用 Maven 重新打包（`mvn clean package -DskipTests`），生成的 jar 才会包含你的改动。
