## 四、🔴 刚需（5 项）

### 4.1 预约排队

- **是什么**：书被借光后读者可排队；前面的人还书后通知下一位「7 天内来取，否则顺延」。
- **当前实测状态**：**无**。`grep "reserv|预约|reservation"` 在 `backend/src/main/java` **零匹配**。
- **为什么刚需**：答辩必问「书 0 本了，读者想借怎么办」，现在只能答"没办法"；Koha、SLiMS 与国内高校（复旦预约书柜/南宁师大委托）**全线具备**；且与已有巡检机制天然衔接（预约到期不取如何回收属数据一致性）。
- **实现要点**：新增 `reservation` 表（book_id / user_id / queue_no / status / expire_time）；还书时触发队首通知（依赖 5.1 通知通道）；定时任务回收过期预约。
- **代价**：约 3 天。
- **影响面**：**页面 16 → 17**（新增"我的预约"或并入"我的书架"作第 4 个 Tab，则页面数不变）；论文第五章需新增一节；测试新增 1 个套件。

### 4.2 续借查欠费（规则联动补口）【2026-10-22 复审新增】

- **是什么**：有未缴罚金的读者不允许续借——"欠费→权限联动"。
- **当前实测状态**：**缺口确认**。`BorrowServiceImpl.renew` 只校验状态/逾期/续借次数，**不查未缴罚金**（借书 `borrow()` 查了 `unpaid`，续借漏了）。对照：Koha `OPACFineNoRenewals`（欠费禁续借）、复旦"逾期即暂停借书权限"——真实系统全线联动。
- **为什么刚需**：这不是新功能而是**与真实系统的规则差距**；答辩演示被评委试出来（欠着钱还能续借）会减分。
- **实现要点**：`renew` 复用 `borrow()` 的 unpaid 查询 + 1 条测试断言（欠费续借被拒）。
- **代价**：**< 0.5 天**。
- **影响面**：接口数不变、表结构不变；测试 +1 项。

### 4.3 读者自助注册（带限流防刷）

- **是什么**：读者自己填手机号、设密码办卡，办完即可借书。
- **当前实测状态**：**无**。`AuthController` 只有 `@PostMapping("/login")` 一个接口；读者账号由管理员在 `UserController` 的 `@PostMapping 新增用户` 建立。
- **为什么刚需**：真实馆 2000 读者不可能由管理员逐个录入。Koha 有 self-registration，同类项目 A 有 `/api/auth/register`。
- **实现要点**：`POST /auth/register`（默认 READER 角色、status=1）+ 注册页；手机号/用户名唯一校验；密码强度校验；**注册接口必须限流**（复用现有登录防爆破组件）——公开注册不加限流等于新增 DoS/灌水面。
- **代价**：约半天。
- **影响面**：页面数不变（注册页可作 Login.vue 内的切换态）；接口 44 → 45；论文 2.3 角色权限小节需补一句。

### 4.4 Excel 批量导入

- **是什么**：从购书系统导出的表格，一键导入几千本书。
- **当前实测状态**：**无**。`pom.xml` 无 POI / EasyExcel 依赖；无导入接口。
- **为什么刚需**：新馆开张录 5000 本，现在一本本点"新增"，按每本 30 秒算需 **41 小时**，不可行；SLiMS/Koha 均有套录或批量通道。
- **实现要点**：引入 EasyExcel（比 POI 轻）；`POST /books/import` + 模板下载接口；逐行校验 ISBN 唯一、分类/出版社存在；失败行返回明细。
- **代价**：约 1 天。
- **影响面**：接口 44 → 46；页面数不变（按钮加在"图书档案管理"里）；无需改论文结构，仅在功能表补一行。

### 4.5 报表导出

- **是什么**：馆长要"上月借阅报告"，能导出 Excel 带走。
- **当前实测状态**：**无**。数据总览只有 4 个固定图表（趋势/占比/TOP10/巡检），无导出接口、无 POI。
- **为什么刚需**：真实馆长第一句就是"能导出吗"；SLiMS 以"Robust reporting"为核心卖点。
- **实现要点**：复用 4.4 引入的 EasyExcel；`GET /stats/export` 导出借阅明细/汇总；前端加"导出"按钮。
- **代价**：约 1 天。
- **影响面**：接口 44 → 47；页面数不变。

## 五、🟡 推荐（4 项）

### 5.1 站内通知 + SMTP 邮件【2026-10-22 复审由"中立"升档】

- **是什么**：三类主动通知——**到期提醒**（到期前 3/5 天，对标复旦"流通邮件通知"）、**逾期催还**、**预约到书通知**；站内消息中心（登录即见红点）+ 邮件通道。
- **当前实测状态**：**无主动通知**。仅有登录后的被动展示（找书页个人摘要条）；无 SMTP 配置、无消息表。
- **为什么升档**：复审对照发现**四类基线里通知是标配而非加分项**（Koha、SLiMS 预约提醒、复旦/北大邮件通知）；且它是 **4.1 预约的激活器**——没有到书通知的预约是死功能（读者只能反复刷新查询）。两项应捆绑排期。
- **实现要点**：`notification` 表 + 站内消息中心入口；`JavaMailSender` + SMTP 配置化（断网时站内通知仍可用，邮件失败仅告警，与审计旁路口径一致）；到期扫描可挂预约回收的同一定时任务。
- **代价**：约 1.5 天（与预约捆绑做省 0.5 天）。
- **影响面**：接口 +1~2；论文第五章补一小节；答辩可现场演示真实邮件。

### 5.2 热门借阅排行【2026-10-22 复审新增】

- **是什么**：读者端展示"热门借阅 TOP N"（太原理工微信端同款）。
- **当前实测状态**：**半成品**。`book.borrow_count` 字段与数据现成，前端无任何入口。
- **为什么推荐**：**性价比最高的单项**——读者端最显眼的"像真系统"信号，几乎零后端成本。
- **实现要点**：复用现有接口（或 `/books` 加排序参数），找书页加"热门"入口/标签。
- **代价**：约 0.5 天。
- **影响面**：接口可能 +1；页面数不变。

### 5.3 读者额度管理

- **是什么**：读者除"正常/冻结"外，还有**借阅有效期、最多可借几本、最大欠款额**。
- **当前实测状态**：**无**。"可借 5 册"写死在 `FineConstant`，所有读者一致。
- **为什么推荐**：真实馆按读者类型分级（教师 20 本 / 学生 5 本）；Koha 按 reader class 区分。
- **口径说明**：这是**按人的数据化额度**，不破坏"全局规则写死 + 巡检守护"的答辩亮点（写死的是全局参数，分级的是读者属性）。
- **代价**：约 1 天。
- **影响面**：`sys_user` 表加字段；借书校验逻辑改动（`BorrowServiceImpl` 防超借处需改）；论文表 5-x 需补列。

### 5.4 一键部署（Docker）

- **是什么**：一条命令拉起 MySQL + 后端 + 前端。
- **当前实测状态**：**无 Docker**。`deploy/` 下有 start.sh / stop.sh / backup.sh / log_cleanup.sh / nginx.conf（Linux shell 方案）。
- **为什么推荐**：换机器不必重配环境；答辩演示"一条命令启动"很直观。
- **代价**：约 1 天。
- **影响面**：代码零改动；`deploy/` 增加 Dockerfile / docker-compose.yml；部署说明需更新。

## 附录 B：⛔ 完全不推荐（6 项）

| 功能 | 为什么做了反而有害 |
