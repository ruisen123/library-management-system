## 三、主要技术难点（3 点，具体）

### 难点 1：借阅流程的多表事务一致性与库存防超借

**具体表现：**
借书操作一次性涉及 3 张表的联动写入——`borrow_record`（生成借阅记录）、`book`（库存 `stock - 1`）、`sys_user`（已借数量 `borrowed_count + 1`）。校验条件有 5 项且缺一不可：

1. 该图书库存 > 0；
2. 该读者当前借阅数未达上限（如最多 5 本）；
3. 该读者名下无逾期未归还图书记录；
4. 该读者名下无未缴清罚金；
5. 读者状态正常（未冻结 / 注销）。

**实现要点：**
- 校验 + 扣减 + 写入必须在同一事务内完成，使用 Spring 的 `@Transactional` 保证原子性；
- 库存扣减不能采用"先查再改"两步操作（存在并发超借漏洞），需使用**条件更新**语句：`UPDATE book SET stock = stock - 1 WHERE id = #{id} AND stock > 0`，通过受影响行数判断成败；
- 逾期罚金在还书时由 SQL 的 `DATEDIFF(当日, due_date)` 按天 × 罚金单价（0.5 元/天）计算，金额固定保留两位小数（与 `DECIMAL(10,2)` 对齐），避免在 Java 内存中逐条遍历。

### 难点 2：基于 RBAC 的三角色权限体系前后端联动

**具体表现：**
系统包含 3 种角色——**读者**（检索图书、查看个人借阅、续借）、**图书管理员**（图书 / 读者档案维护、借还办理）、**系统管理员**（用户与角色分配、系统参数、统计总览）。同一套页面与接口对不同角色暴露的内容和可执行的操作不同。

**实现要点：**
- 后端：登录签发 JWT（含用户 ID 与角色），拦截器统一解析 Token，配合自定义注解 `@RequireRole({ADMIN})` 实现接口级权限校验，越权访问返回 403；
- 前端：登录后按角色动态生成路由（Vue Router 4 的 `addRoute()`）与左侧菜单，登录/注销时动态增删路由；
- 组件级：页面可见性由动态路由与角色菜单保证（如"办理还书"位于图书管理员专属页面），另预留 `v-role` 自定义指令支持按钮级控制；需保证前端隐藏与后端校验双重兜底。

### 难点 3：多表关联的动态分页查询与借阅统计报表

**具体表现：**
- 图书检索支持**书名 / 作者 / ISBN 关键词模糊、分类下拉、仅看有库存**等条件的任意组合分页（分类为一级平铺，固定按上架先后倒序），`book` 关联 `category`、`publisher` 的名称由服务层批量查询填充展示；
- 统计总览页需输出：月度借阅量趋势（近 12 个月）、分类借阅占比、借阅热度 TOP10 图书。

**实现要点：**
- 组合条件使用 MyBatis-Plus 的 `QueryWrapper` 动态拼装（非空才拼接），分页插件 `PaginationInnerInterceptor` 完成物理分页，自定义聚合走注解 SQL（`@Select`），联表名称展示由服务层批量填充；
- 趋势按借出日期 `borrow_date` 月度分组统计，"某月无借阅"由服务层补零显示为 0 而非断线；
- 聚合统计全部在 SQL 层用 `GROUP BY` + 聚合函数完成，前端以 ECharts 渲染趋势折线与分类饼图（借阅热度 TOP10 以表格呈现），避免全量拉取数据到内存计算。
