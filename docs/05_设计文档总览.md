## 一、系统概述

| 项目 | 内容 |
|------|------|
| 题目名称 | 基于SpringBoot+Vue的图书借阅管理系统设计与实现 |
| 系统简称 | LibMS |
| 一句话功能 | 面向中小型图书馆，提供图书档案管理、读者管理、借书/还书/续借全流程处理、逾期罚金计算与借阅统计分析的一体化 Web 管理系统 |
| 系统定位 | B/S 架构 Web 应用，仅 PC 浏览器访问，无移动端 |
| 核心痛点 | 馆藏账实不符、借阅记录难追溯、逾期无人监督、馆藏结构无数据支撑 |
| 难度定位 | 基础 CRUD + 典型业务逻辑（事务、权限、统计），无高并发/复杂算法/付费 API |

**核心业务规则（全程统一定值）：**

| 规则项 | 取值 |
|--------|------|
| 读者可借上限 | 5 册 |
| 借期 | 30 天 |
| 逾期罚金 | 0.5 元/天（还书时自动计算登记，线下收取后标记已缴） |
| 续借 | 每册限 1 次，延长 30 天（自原应还日期起算）；逾期不可续借 |
| 借书前置校验 | 读者状态正常 + 在借未达上限 + 无逾期未还 + 无未缴罚金 + 库存 > 0 |

**系统边界：** 做——登录鉴权（RBAC）、档案 CRUD、借/还/续/罚、检索、个人借阅、统计总览；不做——移动端、在线支付、短信推送、预约/推荐、高并发分布式架构、第三方 API 对接。

## 五、核心业务流程

### 5.1 借书办理

| 项目 | 内容 |
|------|------|
| 前置条件 | 管理员已登录；读者状态正常、在借 < 5、无逾期未还、无未缴罚金；图书库存 > 0 |
| 后置条件 | 新增借阅记录（状态=在借，应还=当日+30 天）；`book.stock - 1`；`sys_user.borrowed_count + 1` |
| 主流程 | 检索读者 → 系统校验（状态/额度/逾期/罚金）→ 扫描 ISBN → 确认借出 → 事务内【条件更新扣库存 `AND stock > 0` → 判断受影响行数 → 插入借阅记录】→ 提交 → 刷新库存与在借数 |
| 异常处理 | ①额度已满→提示先归还；②库存不足/并发超借（受影响行数=0）→事务回滚提示重试；③有逾期或欠费→提示先处理；④账号冻结→终止 |

```
开始 → 校验读者 → [不通过]提示原因 → 结束
                → [通过] → 确认借出 → 条件更新扣库存 → [行数≠1]回滚+提示 → 结束
                                              → [行数=1]插入借阅记录 → 提交 → 提示成功 → 结束
```

### 5.2 还书办理（含逾期罚金）

| 项目 | 内容 |
|------|------|
| 前置条件 | 管理员已登录；存在该读者状态=在借的记录 |
| 后置条件 | 记录状态=已还、归还日期=当日；`book.stock + 1`；逾期时生成罚金记录（金额=逾期天数×0.5，状态=未缴） |
| 主流程 | 检索读者在借清单（标注逾期）→ 选中归还 → 事务内【更新记录状态与归还日期 → `DATEDIFF(当日, 应还日期)` 计算逾期 → 逾期则插入罚金记录 → 库存+1】→ 提交 → 提示（含应收罚金） |
| 异常处理 | ①重复归还（状态非在借）→提示勿重复操作；②逾期→罚金登记并提示线下收取后标记；③图书破损/遗失→走"赔偿登记"（手工金额写入罚金表，借阅记录状态=已赔偿，库存不恢复） |

```
开始 → 选中在借记录 → [状态≠在借]提示重复 → 结束
                     → [在借]更新为已还 → 计算逾期天数 → [>0]生成罚金记录 → 库存+1 → 提交 → 结束
                                                        → [≤0]库存+1 → 提交 → 结束
```

### 5.3 读者在线续借

| 项目 | 内容 |
|------|------|
| 前置条件 | 读者已登录（JWT）；记录归属本人、状态=在借、未逾期、`renew_count = 0` |
| 后置条件 | 应还日期 = 原应还日期 + 30 天；`renew_count = 1` |
| 主流程 | 我的借阅 → 点击续借 → 确认弹窗 → 携 JWT 请求 → 后端校验（归属/状态/逾期/次数）→ 更新应还日期与续借次数 → 提示成功刷新 |
| 异常处理 | ①已逾期→提示尽快归还；②已续借过→提示每册限一次；③越权（记录非本人）→返回 403（全局异常处理器记录告警日志） |

```
开始 → 点击续借 → [非本人记录]403（告警日志） → 结束
                → [本人]校验[在借 且 未逾期 且 未续借]
                      → [不满足]提示具体原因 → 结束
                      → [满足]应还日期+30天、次数=1 → 提示成功 → 结束
```

### 5.4 预约排队（2026-10-22 新增）

| 项目 | 内容 |
|------|------|
| 前置条件 | 读者已登录、账号正常；图书有馆藏（未全部借出）；未重复预约且未在借该书 |
| 后置条件 | `reservation` 新增"排队中"（分配 queue_no）；还书后队首"待取书"（7 天）；待取读者借书后"已完成"；到期未取"已过期"并顺延 |
| 主流程 | 找书页预约 → 锁定图书行校验库存/重复 → 分配序号写入 → 还书触发队首待取 → 读者到馆借书（预约优先）→ 借书成功置完成 → 过期定时/手动回收并顺延 |
| 异常处理 | 有未被占用副本且无人排队→预约直接转"待取书"（不再提示"请直接借阅"）；队尾借待取副本→提示前方还有 N 位；无预约者抢最后待取副本→拒绝；冻结/删除/改角色→自动取消预约；删除有有效预约的图书→拒绝 |
| 库存口径 | 待取预约不扣 `book.stock`，借书时按"待取预约数"保护队首；巡检 R1"总册数=可借+在借+已赔偿"口径不变 |

```
有馆藏 → 预约 → 锁定图书行 → 校验 → [无人排队且仍有未被占用副本] 直接预留"待取书" / [否则] 分配 queue_no → "排队中"
还书 → 库存+1 → 队首待取（7天）→ 队首本人借书 → 已完成
7天未取 → 定时/手动回收 → 已过期 → 顺延下一位
```

## 六、数据库设计（MySQL 8.0 / library_db / 10 张表）

### 6.1 ER 关系说明（文字版）

| 主表 | 关系 | 从表 | 说明 |
|------|------|------|------|
| category | 1 : N | book | `book.category_id` → `category.id` |
| publisher | 1 : N | book | `book.publisher_id` → `publisher.id` |
| sys_user | 1 : N | borrow_record | `borrow_record.user_id` → `sys_user.id`（读者借阅流水） |
| book | 1 : N | borrow_record | `borrow_record.book_id` → `book.id`（图书借阅流水） |
| sys_user | 1 : N | fine_record | `fine_record.user_id` → `sys_user.id`（读者罚金） |
| borrow_record | 1 : N | fine_record | `fine_record.borrow_id` → `borrow_record.id`（逾期/赔偿挂靠借阅） |
| sys_user | 1 : N | notice | `notice.publisher_id` → `sys_user.id`（管理员发布） |
| sys_user | 1 : N | operation_log | `operation_log.user_id` → `sys_user.id`（操作人，可 NULL） |
| book | 1 : N | reservation | `reservation.book_id` → `book.id`（图书预约队列） |
| sys_user | 1 : N | reservation | `reservation.user_id` → `sys_user.id`（读者预约） |

> 核心链路：`sys_user` —`borrow_record`— `book`（借阅金三角）；`borrow_record` — `fine_record`（还书联动罚金）；`book` / `sys_user` — `reservation`（预约排队）。物理外键统一 `ON DELETE RESTRICT ON UPDATE CASCADE`；档案表（sys_user/category/publisher/book/notice）含逻辑删除 `deleted`，流水表与预约表不删（预约用状态流转）。

### 6.3 索引与事务要点

| 类别 | 要点 |
|------|------|
| 补充索引（`idx_*` 共 18 个） | idx_book_isbn；idx_book_title(20)；idx_book_borrow_count；idx_user_status(user_id,status)；idx_user_deleted_create_time(deleted,create_time)；idx_user_role_status(role,status)；idx_borrow_date；idx_due_status(due_date,status)；idx_fine_user_status(user_id,status)；idx_notice_status；idx_log_create_time；idx_username；idx_reader_no；idx_category_name；idx_publisher_name；idx_reservation_book_status(book_id,status,queue_no)；idx_reservation_user_status(user_id,status)；idx_reservation_expire(status,expire_time)（另有 borrow_record.book_id 外键自动索引） |
| 唯一索引 | 生成列唯一索引（未删除唯一、逻辑删除后释放）：uk_sys_user_username；uk_sys_user_reader_no；uk_book_isbn；uk_category_name；uk_publisher_name；预约唯一索引：uk_reservation_book_queue(book_id,queue_no) |
| 事务铁律 | 借书三步（条件更新扣库存→插记录→更新 borrowed_count）、还书三步（更新记录→库存+1→插罚金）与预约状态流转各自整事务提交，任一步失败整体回滚；待取预约不扣库存，借书时按"待取数"保护队首 |
| 冗余字段 | `book.stock` / `book.borrow_count` / `sys_user.borrowed_count` 以 `borrow_record` 为事实源对账 |
