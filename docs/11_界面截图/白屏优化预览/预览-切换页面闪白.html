切换页面"闪白"——量化结果与方案预览

LibMS · 2026-09-15 · 真实点击菜单触发 SPA 路由切换，3 角色 16 个页面逐页实测
先说一处纠正：上一轮"总白平均 77ms"是用 page.goto() 整页刷新测的， 和你实际"点菜单切页面"根本不是一回事。这次改成真实点击侧边菜单重测，结论也随之变了。

一、那个"白"到底是什么

逐帧 + MutationObserver 追踪后，一次切换的真实时间线是这样的：

  • 点击后 12~58ms：旧页面还显示着，正在等新页面的代码（懒加载）就绪 —— 这段时间画面是正常的
  • 同一瞬间：旧内容被清空、新页面挂载并套上 v-loading 遮罩
  • 再过 ~55ms：接口返回，遮罩撤掉，新内容"啪"地出现

关键证据是最后一列 "空卡窗口"平均 −6ms（负数说明遮罩出现得比换页还早）。 也就是说：不存在"先变成一片纯白、再闪出新界面"的独立阶段。

你看到的"白"，就是 v-loading 那个 rgba(255,255,255,.9) 的白色遮罩，盖在一张本来就白的卡片上（.page-card 是 #fff）。 所以体感是"内容突然没了，剩一张白卡 + 转圈"，然后"啪"地弹回来。

三、三个方案的实际效果

① 遮罩改灰 --el-mask-color —— 实测基本无效

像素级比对（内容卡片区域）：差异平均仅 2.24%，主色调从 rgb(255,255,255) 变成 rgb(246,248,251) —— 只差 9/255，约 3.5% 亮度，肉眼分辨不出来。

原因很直接：遮罩是盖在白色卡片上的。把"90% 白"换成"88% 浅灰"，合成结果当然几乎一样。 只有 2 个页面（数据总览、图书详情，根节点不是 .page-card）能有点效果。

② 新内容淡入（0.18s） —— 有效，正好治"闪出"

它不缩短任何时长（中位 55 → 54ms），但把"啪一下弹出来"变成"渐显"。 为了让你看清中间态，下面这张把动画放慢了约 12 倍（实际是 0.18s）：

代价：一条 CSS 动画，渲染开销可忽略。

③ 菜单 hover 预加载 chunk —— 没必要

实测单页 chunk 拉取 13.7~16.0ms（dev，已编译后），49~68KB。

但关键是：Vue Router 会先把懒加载组件取好、再切换视图 —— 也就是 chunk 加载的时候， 旧页面还在屏幕上（这正是"旧页消失"要等到 12~58ms 才发生的原因）。 这段时间用户看不出任何变化。

所以 ③ 省下的那 ~14ms，落在了一个"本来就没有视觉异常"的窗口里，白忙一场。 另外生产构建的 chunk 是预编译好的，更不会有这个问题。

四、要消除它，真正该动的是遮罩本身

既然"白"= 一张空卡片 + 90% 白遮罩，那有效的做法是让这个"空"不那么空：

  • 甲（改动最小）：降低遮罩不透明度（0.9 → 0.5 左右），让底下的表头/工具栏隐约透出来， 不再是"一片白"。一行 CSS 变量的事。
  • 乙：遮罩只盖表格区域，页面标题和工具栏保持清晰 —— "整个界面变白"的观感基本消失。
  • 丙（改动最大）：用骨架屏替代遮罩，视觉上最平滑。

② 和上面任一条组合都可以，互不冲突。

一句话总结：① 看不出差别（3.5% 亮度）、② 有效（治"闪出"）、③ 白忙（省的时间用户看不见）。 如果你想继续，建议从 甲 + ② 入手，改动依然很小。

五、复现方式

量化脚本.js 放在本目录，运行：

NODE_PATH=<pwcheck>/node_modules node 量化脚本.js

两个前提：后端跑在 8080（java -jar libms-backend-1.0.0.jar --server.port=8080）， 前端 npm run dev；访问必须用 localhost:5173 —— 后端 CORS 只放行这个来源，用 127.0.0.1 会 403。
