# 部署说明

> 系统名称：基于SpringBoot+Vue的图书借阅管理系统（LibMS）
> 部署架构：Nginx（静态资源 + 反向代理）→ Spring Boot（后端 API）→ MySQL 8.0
> 适用范围：Windows / Linux 服务器独立部署

---

## 一、环境要求清单

| 软件 | 版本要求 | 说明 |
|------|----------|------|
| JDK | **21**（LTS） | 后端 `pom.xml` 编译目标为 21，低版本无法运行 |
| Maven | 3.8+ | 后端打包工具（本机实测 3.9.16） |
| Node.js | 18+ | 前端 Vite 5 构建要求（推荐 20/22 LTS） |
| MySQL | 8.0.x | 数据库服务（本机实测 8.0.43） |
| Nginx | 1.18+ | Web 服务器 + 反向代理 |

> 验证命令：`java -version`、`mvn -v`、`node -v`、`mysql --version`、`nginx -v`

## 二、数据库部署

### 2.1 创建数据库 + 建表 + 测试数据（一步完成）

脚本 `docs/04_数据库设计.sql` 已包含「建库 → 建表 → 测试数据 → 索引」全流程，直接执行即可：

```bash
# 将 <你的密码> 替换为实际 root 密码
```

> 脚本已在建库前显式声明严格模式（`STRICT_TRANS_TABLES,NO_ENGINE_SUBSTITUTION`），避免超长输入被静默截断。

### 2.3.1 已有库升级：预约排队表（2026-10-22）

新库执行 `docs/04_数据库设计.sql` 已包含 `reservation`；已有库请先备份，再执行一次：

```bash
mysql -u root -p --default-character-set=utf8mb4 library_db < deploy/sql/2026-10-22_reservation.sql
```

脚本幂等（`CREATE TABLE IF NOT EXISTS`），包含 `reservation` 表、3 个普通索引、1 个唯一索引、2 个外键与 2 个 CHECK（`chk_reservation_status` / `chk_reservation_queue_no`）。执行后全库 `chk_*` 约束共 **13 个**，业务表计数保持不变、`reservation` 为 0。

### 2.3.2 已有库升级：推荐项（读者额度 + 站内通知，2026-10-22）

新库执行 `docs/04_数据库设计.sql` 已自带全部结构；已有库请先备份，再执行：

```bash
mysqldump -u root -p --databases library_db > library_db_before_recommended.sql
mysql -u root -p --default-character-set=utf8mb4 library_db < deploy/sql/2026-10-23_recommended.sql
```

脚本内容：`sys_user` 加 `borrow_limit`/`max_unpaid`/`valid_until`/`email`/`email_notify` 五列，建 `notification` 表（含唯一 `dedup_key` 与两个查询索引），补 6 个 `chk_*`。**每一步都先查 `information_schema` 再执行，可重复运行**（实测在临时库连跑两次，第二次不报错、结果仍为 10 表 / 19 CHECK）。执行后为 **10 张表、19 个 `chk_*`**，业务计数不变、`reservation`=0、`notification`=0。

> ⚠️ 迁移后必须**先升级后端再放流量**：新列有默认值、旧代码可忽略新增列与 `notification` 表，因此向后兼容；但新后端依赖这些列，反过来不成立。回滚只需退回旧 jar，多余列与表保留不影响业务。

### 2.4 定时备份（`deploy/backup.sh`）

脚本 `deploy/backup.sh` 用 `mysqldump` 对 `library_db` 做全量备份（`--single-transaction`，不锁表），自动保留最近 7 天并清理过期文件，对应 `docs/03` 非功能性需求中「数据库每日凌晨自动完整备份、备份保留 ≥ 7 天」。

```bash
# 手动执行一次
bash deploy/backup.sh

# 配置每日 02:00 自动备份（crontab -e 中追加一行）
0 2 * * * bash /usr/local/libms/deploy/backup.sh
```

- 数据库连接参数与 `start.sh` 一致，通过 `DB_HOST` / `DB_PORT` / `DB_USERNAME` / `DB_PASSWORD` / `DB_NAME` 注入；
- 备份目录默认 `/usr/local/libms/backup`（可用 `BACKUP_DIR` 覆盖），文件名形如 `library_2026-09-11_020000.sql`；
- 保留天数默认 7 天（可用 `KEEP_DAYS` 覆盖）；备份失败时错误写入 `$BACKUP_DIR/backup.err` 并以非 0 退出码结束。

> ⚠️ 备份与数据库同盘存储时，磁盘故障会导致数据与备份一并丢失，建议定期将备份拷贝至异机或对象存储。

### 2.5 恢复

```bash
mysql -u root -p --default-character-set=utf8mb4 < /usr/local/libms/backup/library_2026-09-11_020000.sql
```

> 备份命令使用 `mysqldump --databases`，dump 内自带 `CREATE DATABASE IF NOT EXISTS` 与 `USE`：目标库被删或换机后可直接恢复，无需先手工建库。若要恢复到不同库名，需先改 dump 内的库名或按需导入。

## 三、后端部署

### 3.1 打包

```bash
cd backend
mvn clean package -DskipTests
```

打包产物：`backend/target/libms-backend-1.0.0.jar`

### 3.2 生产环境配置

敏感信息（数据库口令、JWT 密钥）通过**环境变量**注入，不写死在配置文件中。其中 `DB_PASSWORD` / `JWT_SECRET` **无默认值，缺失时后端启动即失败**（fail-fast），避免误用默认口令，支持以下环境变量：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| DB_HOST | localhost | 数据库地址 |
| DB_PORT | 3306 | 数据库端口 |
| DB_NAME | library_db | 数据库名 |
| DB_USERNAME | root | 数据库账号 |
| DB_PASSWORD | 无（必须显式注入） | 数据库密码（无默认值，启动前必须显式设置） |
| JWT_SECRET | 无（必须显式注入） | JWT 签名密钥（无默认值，长度 ≥ 32 字节，启动前必须显式设置） |
| FILE_UPLOAD_DIR | ./upload | 文件上传目录 |
| MYBATIS_LOG_IMPL | org.apache.ibatis.logging.nologging.NoLoggingImpl | MyBatis SQL 日志实现。**默认已关闭（安全默认）**——`StdOutImpl` 会把 SQL 语句与全部参数实参（含口令列、姓名、手机号）打到标准输出，故默认取安全值；**开发期需显式设为 `org.apache.ibatis.logging.stdout.StdOutImpl` 才会打印 SQL** |
| MYBATIS_LOG_LEVEL | info | mapper 包日志级别（**默认 info，不打印 SQL 与参数实参**；开发期需显式设为 `debug`） |
| CORS_ALLOWED_ORIGIN | http://localhost:5173,http://127.0.0.1:5173 | CORS 允许的前端来源，逗号分隔多个；生产直连请改为实际前端域名（如 `https://libms.example.com`）；同源 Nginx 代理场景无需改动 |
| APP_TRUST_FORWARDED_HEADER | false | 是否信任 `X-Forwarded-For` 头作为操作日志来源 IP（对应 `app.trust-forwarded-header`）。**默认 false，直取 TCP 对端地址**——该头由客户端可控，实测可伪造任意 IP 写入 `operation_log.ip`；仅当部署于**可信反向代理之后**（由代理覆盖 XFF）时设为 `true` |
| APP_API_DOCS_ENABLED | false | 是否暴露 `/doc.html`、`/v3/api-docs`、`/swagger-ui/**`。**默认 false；本地开发如需调试须显式设 true，生产/容器部署必须保持 false**（`ApiDocsAccessFilter` 在应用层直接返回 404，不再只依赖 Nginx）。knife4j/springdoc 自带的四组开关实测无法关闭静态资源面（2026-09-12 结论），故用本开关兜底；Nginx 层仍保留 404 段作为双保险 |
| KNIFE4J_ENABLE | （不适用） | ⚠️ **实测结论（2026-09-12）**：knife4j/springdoc 的应用层开关（`knife4j.enable`、`knife4j.production`、`springdoc.api-docs.enabled`、`springdoc.swagger-ui.enabled`）**均无法关闭** `/doc.html` 与 `/v3/api-docs` 的访问。关闭文档面请使用上方的 `APP_API_DOCS_ENABLED=false`（应用层）并保留 `deploy/nginx.conf` 的「生产关闭接口文档」段（代理层） |
| JWT_EXPIRE | 86400000（24 小时） | 令牌有效期（毫秒）。本系统无令牌吊销机制（属已评估开放项），生产可注入 `7200000`（2 小时）作为**最小缓解**，缩短令牌泄露后的可用窗口 |
| RETENTION_DAYS | 180 | 操作日志保留天数（供 `deploy/log_cleanup.sh` 使用，按周清理 `operation_log` 中早于该天数的记录） |
| APP_REGISTER_MAX_PER_IP | 5 | 读者自助注册限流：单 IP 窗口内最多注册次数（进程内计数，单实例口径） |
| APP_REGISTER_WINDOW_MINUTES | 60 | 注册限流窗口（分钟） |
| APP_REGISTER_GLOBAL_MAX | 200 | 注册限流全局上限（全进程窗口内，防分布式灌号） |
| APP_RESERVATION_EXPIRE_SCAN_MS | 300000 | 预约过期回收扫描间隔（毫秒，默认 5 分钟） |
| APP_RESERVATION_EXPIRE_DELAY_MS | 60000 | 预约过期回收首次扫描延迟（毫秒，默认启动后 1 分钟） |

> ⚠️ **CORS 已默认收紧**：后端 `CorsConfig` 默认允许 `http://localhost:5173` 与 `http://127.0.0.1:5173`（开发端口，逗号分隔）携带凭证。生产若采用前端直连后端，请通过环境变量 `CORS_ALLOWED_ORIGIN` 设置为实际前端域名；推荐走 Nginx 同源代理（`VITE_API_BASE=/api`），则不存在跨域请求。
>
> ⚠️ **注册限流与反向代理**：注册限流按来源 IP 计数。生产经 Nginx 反向代理时必须设 `APP_TRUST_FORWARDED_HEADER=true`（由 Nginx 覆盖 X-Forwarded-For），否则所有注册请求会共享代理 IP，被 5 次/小时的阈值整体误伤。`deploy/docker` 的 compose 已默认注入 `true`；手工直跑部署仍需自行设置。
>
> ⚠️ **上线后必须逐个修改默认口令**：种子账号（`admin` / `librarian01` / `reader001`）、新增账号默认口令与"重置密码"结果都是 `123456`（`UserServiceImpl.java:101,220`），系统**没有"首次登录强制改密"**。对外提供服务前，请让每个账号登录后在「个人中心 → 修改密码」自助改密（`PUT /profile/password`，需原密码，改密后旧令牌因密码指纹校验立即失效）；管理员也可在「用户管理 → 重置密码」把口令重置回初始值（`PUT /users/{id}/password`，仅系统管理员）。

### 3.3 运行 JAR 包

**Linux（推荐：项目根目录执行启停脚本）：**
```bash
export DB_PASSWORD="<你的数据库密码>"
export JWT_SECRET="<自定义的随机密钥>"
bash deploy/start.sh
bash deploy/stop.sh
```

> `start.sh` 会按脚本自身位置定位 `backend/target`，可从任意目录执行；日志与 PID 固定落在 `backend/app.log`、`backend/app.pid`。探活用 `/books`，不依赖接口文档开关。

**Linux（手工后台运行 + 日志）：**
```bash
export DB_USERNAME="root"
export DB_PASSWORD="<你的数据库密码>"
export JWT_SECRET="<自定义的随机密钥>"
nohup java -jar target/libms-backend-1.0.0.jar --server.port=8080 > app.log 2>&1 &
echo $! > app.pid     # 记录进程号，便于停止
```

> **日志说明**：除上述控制台重定向的 `app.log` 外，应用还会按 `logback-spring.xml` 写入**滚动日志 `logs/libms.log`**
> （按 100MB / 日期滚动，保留 30 天、总量上限 2GB；目录可用 `LOGGING_FILE_PATH` 覆盖），排障建议优先看该文件。
> 每条日志带请求关联 ID（`[requestId]`，也可由调用方通过请求头 `X-Request-Id` 透传），便于把同一次请求的多条日志串起来。

**Windows：**
```powershell
$env:DB_USERNAME="root"
$env:DB_PASSWORD="<你的数据库密码>"
$env:JWT_SECRET="<自定义的随机密钥>"
java -jar target\libms-backend-1.0.0.jar --server.port=8080
```

## 四、前端部署

### 4.1 构建

```bash
cd frontend
npm install
npm run build
```

构建产物：`frontend/dist/`

> 构建前确认 `.env.production` 中 `VITE_API_BASE=/api`（走 Nginx 反向代理）或改为实际后端地址。

### 4.2 前端环境变量配置

`frontend/.env.production`：
```
# 生产环境接口基础路径：
#   /api          → 走 Nginx 反向代理（推荐，同源无跨域）
#   http://域名:8080/api → 直连后端（需后端已开 CORS）
VITE_API_BASE=/api

# 生产构建关闭演示账号一键登录（包含 admin，属于提权入口）
VITE_DEMO_QUICK_LOGIN=false
```

| 变量 | 生产值 | 说明 |
|------|--------|------|
| `VITE_API_BASE` | `/api` | 接口基础路径，`/api` 走 Nginx 反向代理（同源无跨域） |
| `VITE_DEMO_QUICK_LOGIN` | **必须 `false`** | 演示账号一键登录开关：`true` 时登录页出现三个演示账号（**含 admin**）一键登录按钮，等于**提权入口**。`vite build` 默认 mode=production、加载 `frontend/.env.production`（该文件已写死 `false`），所以正常构建是关闭的；但用 `vite build --mode 其他`、或构建上下文缺少 `.env.production`（如手工拼构建目录）时会变成开启。**构建后建议反查产物**：在 `frontend/dist/assets/` 内检索 `演示账号一键登录`、`quick-login-admin`，应为 0 命中。 |
| `VITE_USE_MOCK` | `false` | 本地 Mock 开关，生产必须 `false`（mock 模块为动态 `import()`，`false` 时整体不进产物） |

### 4.3 Nginx 配置

将 `dist` 目录内容复制到服务器（如 `/usr/local/nginx/html/libms`），并配置反向代理（完整配置见 `deploy/nginx.conf`）：

> ⚠️ **必须设 `client_max_body_size 6m;`**（`deploy/nginx.conf` 已改）。图书 Excel 导入允许 5MB，Nginx 默认 1m、此前模板写的 2m 会把 2–5MB 的合法文件在入口层直接 413；本地 Vite 代理不经 Nginx，所以接口层测试测不出来（2026-10-22 容器化验证时发现并修复）。

```nginx
server {
    listen       80;
    server_name  localhost;

    # 前端静态资源
    root   /usr/local/nginx/html/libms;
    index  index.html;

    # Vue Router history 模式：刷新 404 兜底
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端接口反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
    }

    # 上传文件访问
    location /upload/ {
        proxy_pass http://127.0.0.1:8080/upload/;
    }
}
```

> 说明：`proxy_pass http://127.0.0.1:8080/;` 末尾的 `/` 表示**去掉 `/api` 前缀**再转发（后端接口本身无 `/api` 前缀，由前端 Axios 的 `baseURL=/api` 拼接）。

### 5.2 验证系统正常运行

1. **访问首页**：浏览器打开 `http://服务器IP/`，出现登录页（LibMS 品牌区）；
2. **登录**：用 `admin / 123456` 登录，跳转「数据总览」；
3. **测试核心功能**：用户管理页能加载 6 条用户；新增/编辑/冻结操作正常；
4. **接口文档**：仅当显式设置 `APP_API_DOCS_ENABLED=true` 时可访问 `http://服务器IP:8080/doc.html`；默认 false，应用层返回 404，Nginx 层也会关闭文档面；
5. **接口直连**：`curl http://服务器IP:8080/auth/login`（POST admin/123456）返回 code=200。

### 5.3 常见部署问题排查

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 端口占用（8080） | 后端重复启动或他进程占用 | `netstat -ano \| grep 8080` 找 PID；Linux `lsof -i:8080`，`kill <PID>` |
| 跨域报错 | 前端直连后端但未走 Nginx 代理 | 前端 `VITE_API_BASE=/api` 走同源代理；或确认后端 CorsConfig 已开启 |
| 静态资源 404 | 路由刷新后找不到页面 | Nginx 配置 `try_files $uri $uri/ /index.html` |
| 接口 404 | 前端 `/api` 前缀未被正确转发 | 确认 Nginx `proxy_pass` 末尾带 `/`（去掉前缀） |
| 数据库连接失败 | 账号密码错误 / 库未建 / 时区 | 核对 `DB_*` 环境变量；确认 `library_db` 已建；确认 MySQL 已启动 |
| 中文乱码 | 客户端字符集不对 | 执行 SQL 加 `--default-character-set=utf8mb4` |
| 前端 500 | 后端未启动或 8080 不通 | 检查 `app.log` 与滚动日志 `logs/libms.log`、`curl 127.0.0.1:8080` 探活 |
| 切换页面时遮罩盖住整张卡片 | 浏览器不支持 CSS `:has()`，加载遮罩范围优化规则整段失效 | **属预期降级，不影响功能**：`styles/index.css` 中 `.page-card:has(> .el-loading-mask)` 被忽略，回退为"遮罩覆盖整张卡片"的原表现。使用 Chrome / Edge 105+ 即可生效 |
| 界面四周有 8px 白边／打开弹窗后整页右移 | 部署的前端产物是旧的（`body` 尚未归零 margin） | 到 `frontend/` 重新 `npm run build` 并替换 `dist/`。该修复见 `审查归档/01_审查过程全记录/56` §8.8 |
| 弹窗跑到偏左上（未相对内容区居中） | 前端产物是旧的（缺少弹窗居中样式） | 到 `frontend/` 重新 `npm run build` 并替换 `dist/`。该修复见 `审查归档/01_审查过程全记录/56` §8.9；注意侧边栏折叠宽度由 `--libms-aside-w` 驱动，需保证 `Layout.vue` 已随之更新 |

## 六、容器化部署与邮件通道（2026-10-22 新增）

### 6.1 Docker 一键部署（可选，不替换上面的直跑方式）

前置：Docker Desktop 已启动（`docker info` 能返回 Server Version）。首次构建需联网拉基础镜像与依赖。

```bash
cd deploy/docker
cp .env.example .env      # 必填 MYSQL_ROOT_PASSWORD / MYSQL_PASSWORD / JWT_SECRET(≥32B)
docker compose up -d --build
# 浏览器打开 http://localhost:9088（本机 .env 设为 9088；默认 8088）   登录 admin / 123456
docker compose ps                  # 三服务均应为 healthy
docker compose down               # 停止并保留数据卷
docker compose down -v            # 停止并清空卷（下次 up 重新导入 docs/04 种子）
```

要点：

- **首次启动慢**：MySQL 空卷要先建系统表再执行挂载的 `docs/04`（实测本机约 2 分钟），健康检查宽限期已设为 300s；期间 `up` 会停在 `mysql Waiting`，属正常。
- **只有前端映射端口**（默认 8088，可用 `WEB_PORT` 改；本机 `deploy/docker/.env` 为 9088，访问 `http://localhost:9088`）；MySQL 与后端只在容器网络内可达。
- **换端口/域名必须同步 `CORS_ALLOWED_ORIGIN`**：浏览器带 `Origin` 的请求会走 CORS 校验，默认值已按 `WEB_PORT` 自动生成 `localhost` 与 `127.0.0.1` 两个来源；实测若不配置，登录会 403 `Invalid CORS request`（curl 不带 Origin，测不出来）。
- **可信代理头默认已开**：compose 的 backend 环境注入 `APP_TRUST_FORWARDED_HEADER=true`（Nginx 以 `$remote_addr` 覆盖 XFF，无法伪造首段），否则注册限流会按 Nginx 容器 IP 全站共享、审计 IP 全变 172.x。
- **接口文档默认关闭**：compose 注入 `APP_API_DOCS_ENABLED=false`，即使直连后端 8080 也无法匿名读取 `/v3/api-docs` 与 `/doc.html`。本地开发直跑也默认 false，仅调试时显式设 true。
- 数据初始化只在**空卷**首次启动时执行；改过 `docs/04` 后想生效需 `docker compose down -v` 再 up。
- **封面上传持久化**：compose 为 backend 挂 `backend-upload:/app/upload`；镜像已预建该可写目录，全新卷可直接上传，`down`/重建容器不丢封面，`down -v` 会连同 MySQL 卷一起清空。复用旧卷若报“封面保存失败”，按 `deploy/docker/README.md` 的旧卷属主修正命令处理。
- **`MYSQL_DATABASE` 必须保持 `library_db`**：`docs/04` 内硬编码库名；改成其他值会得到空库（后端连上但无表）。
- 与本机直跑共用同一份 `docs/04_数据库设计.sql`，表结构与种子完全一致。

实测验收（2026-10-22）：三容器 healthy；全新卷初始化后 **10 表 / 19 CHECK**、中文数据无乱码；经 Nginx `POST /api/auth/login` 返回 200；`GET /api/books?sort=popular` 顺序正确；`POST /api/notifications/scan` 生成 3 条；**3MB 文件上传返回 HTTP 200 + 业务码 400（"未读取到数据行"），不再是 413**；容器版前端 Playwright 登录成功、看板渲染 2 张 ECharts、控制台 0 错误。

### 6.2 邮件通知通道（默认关闭）

站内通知不依赖邮件；未启用时通知照常生成与展示，`email_status` 直接记 3（跳过）。启用需注入以下环境变量（直跑用 shell 变量，容器写 `.env`）：

| 变量 | 说明 |
|---|---|
| `MAIL_ENABLED` | `true` 才真正外呼；默认 `false` |
| `MAIL_HOST` / `MAIL_PORT` | SMTP 服务器与端口 |
| `MAIL_USERNAME` / `MAIL_PASSWORD` | 凭据（只放环境变量/`.env`，**不要提交、不要随包外发**） |
| `MAIL_SMTP_AUTH` / `MAIL_STARTTLS` | 多数服务商需 `true` / `true` |
| `MAIL_FROM` | 发件人，默认 `no-reply@libms.local` |
| `MAIL_MAX_ATTEMPTS` / `MAIL_BATCH_SIZE` / `MAIL_SKIP_IF_READ` | 最大尝试次数 / 单轮批量 / 站内已读则跳过邮件 |

投递语义：`notification` 表自身兼作 outbox，定时任务每分钟认领一批（条件更新置"发送中"）后在事务外发送，成功置 1、失败按 1/5/30/120/360 分钟退避重试、超过上限置 4；进程崩溃残留的"发送中"超 10 分钟自动回收。**为"至少一次"语义**，极端情况下可能重复一封，正文不含敏感信息。读者需先在个人中心填写邮箱且保持"邮件通知"开启才会收到。

> 真实 SMTP 外呼未做验证（无凭据）；已用本地假 SMTP 端到端验证"投递成功 / 关闭通知跳过 / 不可达重试 / 恢复后重投 / 主库净零"五条链路，见 `test/mail/run_mail_test.py`（14 项）。

## 七、2026-10-22 审计修复说明

- **操作日志事务语义**：借书、还书、续借、缴费、赔偿、用户/图书/公告/分类/出版社等业务写操作，审计日志与业务在同一事务内提交；日志写失败时业务回滚，保证“接口成功 ⇔ 业务和审计都已落库”。登录、巡检动作属于旁路留痕，采用 best-effort，日志失败只写应用日志，不影响登录/巡检结果。不要再把审计日志改成 `REQUIRES_NEW`：那会让每个写请求同时占用两条数据库连接，连接池 10 时慢写并发会超时。
- **还书/赔偿的删除实体保护**：图书或用户已被逻辑删除时，还书/赔偿返回业务错误并回滚，避免库存或 `borrowed_count` 静默漂移；先恢复图书/用户再办理。
- **历史分页**：`GET /my-borrows` 新增可选 `history=true`，返回排除在借的记录并支持服务端分页；前端“我的借阅-历史/罚金”不再全量拉取、不再有 100 页静默截断。
- **权限默认拒绝**：没有显式 `@RequireRole` 的接口默认 403；公共接口（个人中心、公告读取等）已显式标注全角色。

## 附：裸 `java -jar` 启动的接口文档面风险（2026-10-24 R3 审查补充）

`application.yml` 里 `app.api-docs.enabled` 的默认值取自环境变量 `APP_API_DOCS_ENABLED`，**缺省即 false**；直接 `java -jar` 启动时接口文档默认 404。仅当显式设 true 时才开放；`/doc.html`、`/v3/api-docs/**` 仍位于 `WebMvcConfig` 豁免清单内。

更麻烦的是：`app.api-docs.enabled`、`knife4j.production`、`springdoc.api-docs.enabled`、`springdoc.swagger-ui.enabled` **四组开关逐一实测都关不掉这两个入口**（页面由依赖内静态资源提供），真正起作用的拦截是 `ApiDocsAccessFilter`。

→ 生产部署须同时满足：① `APP_API_DOCS_ENABLED=false`（默认已关闭）；② 保留 `ApiDocsAccessFilter`（勿删）；③ 容器/网关层再限一次路径。`deploy/docker/docker-compose.yml` 已置 false；本地调试需开文档时须显式设 true。
