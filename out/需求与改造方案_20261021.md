# LibMS 界面与体验改造方案

> 生成时间：2026-10-21 22:05　|　项目：基于 SpringBoot + Vue 的图书借阅管理系统（朱瑞森毕业设计）
> 用途：作为改造提案，可直接与其他方案对照评审

---

## 0. 一句话概括

系统功能是完整可用的（44 接口 / 8 表 / 353 项后端测试全绿），但**界面停留在"能跑"的层面**：四个核心页面的卡片布局数量为 0，信息无层级、操作路径长、三个角色共用一套外壳。本方案在不破坏现有功能与测试的前提下，分七块把界面改造到"可直接使用"的水平。

## 2. 现状诊断（全部可复核）

### 2.1 视觉层面：没有信息层级

四个核心页面统计（源码实测）：

| 页面 | 行数 | el-card | el-button | el-table | 说明 |
|---|---|---|---|---|---|
| 读者找书 BookSearch.vue | 103 | **0** | 3 | 1 | 纯表格 |
| 馆员借还 BorrowHandle.vue | 468 | **0** | 9 | 1 | 双 Tab + 两个表格 + 步骤标题 |
| 读者借阅 MyBorrow.vue | 244 | **0** | 1 | 1 | 三 Tab 表格 |
| 管理员总览 Dashboard.vue | 282 | **0** | 1 | 1 | 图表 + 表格 |

**结论：全站零卡片布局，所有信息同等权重。**这是"一眼看过去不知道从何下手"的直接原因。

### 2.2 操作层面：核心路径过长

馆员办理**一次借书**实测路径（BorrowHandle.vue:9-80）：

```
输读者证号 → 点「查询」 → 在表格点选一行 → 输书名 → 点「查询」 → 在表格点选一行 → 点「确认借出」
= 7 次交互
```

**还书**更绕：输读者 → 查询 → 选中 → 再找到那本书 → 选书 → 确认。

参考真实做法（天津中医药大学自助借还机）：**放上书 → 自动识别 → 确认**，全程无需手动录入图书信息。

### 2.3 读者端：只能看，不能借

- 读者看到的是表格（书名/作者/分类/出版社/可借数），不是"书"
- 点「查看详情」后无处可去：借书接口 `BorrowController:34` 仅 `{ADMIN, LIBRARIAN}`
- 读者流程在此断裂

### 2.4 数据现状

- `book.cover` 字段**已存在**（varchar(255)，注释"封面图片地址（扩展功能预留）"），但 6 本书**全部为 NULL**
- 8 张表中**无排班表**，"值班人员"无法直接取数

### 2.5 权限矩阵不一致（已修复）

改造前：

| 资源 | ADMIN | LIBRARIAN | READER |
|---|---|---|---|
| 分类管理 | ✅ 增删改 | ❌ | 只读 |
| 出版社管理 | ✅ 增删改 | 只读 | ❌ |
| **图书** | **❌ 全部** | ✅ 增删改查 | 只读 |
| 借还办理 | ❌ | ✅ | ❌ |
| 罚金操作 | ❌ | ✅ | 只读 |

**管理员能管图书的"分类"和"出版社"，却管不了"书"本身**，逻辑倒置。

## 3. 真实系统与开源项目依据

### 3.1 真实高校图书馆的三种借阅方式

| 方式 | 操作者 | 依赖 | 出处 |
|---|---|---|---|
| 柜台办理 | 馆员 | 无 | 所有图书馆的兜底 |
| 自助借还机 | 读者 | **RFID 标签 + 硬件** | 天津中医药大学图书馆《自助借还机使用方法》 |
| 线上自助 | 读者 | 仅登录态 | 武汉东湖学院：凭电子借阅证在学习通/公众号自行办理借还 |

原文摘录（天津中医药大学）：
> 办理借书：选择"借书"选项，将需要借阅的图书平整放置在指定识读区域，设备可单次识别 5 本以上图书的 RFID 标签，系统会自动统计图书数量，按提示确认借书信息。
> 办理还书：将待归还的图书放置到指定识读区域，设备将自动完成图书识别与还书状态更新，**全程无需额外手动录入图书信息**。

### 3.2 借阅规则横向对比

| 项 | 本项目 | 武汉东湖学院（学生） | 说明 |
|---|---|---|---|
| 可借数量 | 5 本 | 15 册 | 本项目更保守，符合"中小型图书馆"定位 |
| 借期 | 30 天 | 30 天 | 一致 |
| 续借 | 1 次（+30 天） | 5 次 | 本项目更严格 |
| 逾期费 | 0.5 元/天 | 0.1 元/天，累计 5 元停借 | 均属合理区间 |

**结论：现有业务参数合理，不建议为"更像真实"而改动。**改动会连带论文表格、测试断言、答辩口径，收益低。

### 3.3 可对照的开源项目

| 项目 | 技术栈 | 可借鉴点 |
|---|---|---|
| [itcoderyhl/book-manage-server](https://github.com/itcoderyhl/book-manage-server) | SpringBoot + Vue + ElementUI + **ECharts** | 三角色（管理员/图书管理员/学生）；**管理员首页即数据统计**；**图书管理支持上传图片**；馆员同样可管图书 |
| [hncjxywyh/LibraryManeger](https://github.com/hncjxywyh/LibraryManeger) | **Spring Boot 3.2 + Vue 3** | 与本项目技术栈完全一致，可对照页面结构 |

**关键印证**：参考项目中的管理员**同样具备图书管理权限**——R4 的诉求是行业通行做法，不是特例。

## 4. 改造方案（七块）

### 块 1 · 图书封面（覆盖 R5）

**问题**：`cover` 字段存在但全为 NULL，只做"有图显示图"会导致页面依旧空白。

**方案：双层降级**

| 情况 | 展示 |
|---|---|
| `cover` 有值 | 加载图片，失败时降级 |
| `cover` 为空 | **自动生成渐变封面**：书名首字（或前两字）+ 按分类取色 |
| 图片加载失败 | 同上自动封面 |

**产出**：新建 `components/BookCover.vue`，供卡片墙、详情、借还页复用。
**价值**：6 本书立刻呈现 6 种不同配色，视觉上从"表格"变为"书架"。

---

│ │封面 │ │封面 │ │封面 │ │封面 │ │封面 │             │ ← 卡片墙
│ │书名 │ │书名 │ │书名 │ │书名 │ │书名 │             │
│ │可借7│ │可借5│ │借完 │ │可借3│ │可借6│             │
│ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘             │
└──────────────────────────────────────────────────────┘

**改动点**

4. 顶部个人摘要条（在借数 / 最快到期 / 欠费）

### 块 3 · 馆员端「借还办理」（覆盖 R2、R3）

**现状**：468 行，7 次交互/单。

**目标形态：扫码式输入**

```
┌──────────────────────────────────────────────────┐
│ 借书 │ 还书                                     │

│    │ 📕 深入理解计算机系统   可借 7 册      │     │
│    └──────────────────────────────────────┘     │
│          ┌────────────────────────┐             │
│          │    ✅ 确认借出          │             │ ← 大按钮常驻
│          └────────────────────────┘             │

```

**改动点**
1. 输入框**实时联想下拉**（输证号/书名即出候选），回车选中，去掉「查询」按钮与表格点选

4. 成功后**大号反馈 + 自动清空**，准备下一单
5. 交互次数：**7 次 → 3 次**（输证号回车、输书名回车、点确认）

### 块 4 · 三角色首页差异化（覆盖 R1、R2、R6）

**现状**：三角色共用 `Layout.vue`，仅菜单不同。

**方案：按角色定位给不同首页**

| 角色 | 首页 | 内容 |
|---|---|---|
| 读者 | 找书 + 我的书架 | 搜索框、在借卡片、到期提醒、可借推荐 |
| 馆员 | **今日工作台** | 今日借出/还入数、**逾期未还名单**、待缴罚金、**今日在岗人员**、一键进借还 |
| 管理员 | 数据总览（升级） | 卡片式指标 + ECharts 趋势 + **巡检健康卡**（现有三个创新点之一，需突出） |

**"在岗人员"实现（R6）**
- **不新建表**，从 `operation_log` 推导：今日有操作记录的工作人员 = 在岗
- 展示：姓名 + 角色 + 最近操作时间 + 最近动作
- 数据真实可追溯（答辩可打开数据库验证），避免为凑功能造假数据

**新增文件**：`views/reader/ReaderHome.vue`、`views/librarian/LibrarianHome.vue`
**路由调整**：`ROLE_HOME` 中 READER 与 LIBRARIAN 指向新首页（页面总数 16 → 18）

### 块 6 · 视觉统一与动效（覆盖 R9、R10）

**统一设计变量**

| 变量 | 值 |
|---|---|
| 圆角 | 卡片 12px / 按钮 8px / 标签 4px |
| 阴影 | 三级（静止 / 悬停 / 浮层） |
| 主色 | 青绿渐变（呼应登录页氛围） |
| 间距 | 8 的倍数栅格 |

**动效清单（仅 4 处，克制）**

| 做 | 不做 |
|---|---|
| 页面切换淡入（200ms） | 全屏粒子背景 |
| 关键数字滚动（0→8274） | 卡片错峰飞入 |
| 卡片/按钮悬停微上浮 | 3D 翻转 |
| 列表加载骨架屏 | 复杂路径动画 |

**理由**：后台系统的动效目标是"反馈明确"，不是"炫技"。过度动效会拖慢操作感知。

### 块 7 · 图书智能助理（覆盖 R8）

**关键决策：本地意图识别，不接外部大模型**

| 维度 | 接大模型 API | 本地规则（本方案） |
|---|---|---|
| 断网可用 | ❌ | ✅ |
| 结果可复现 | ❌ 同问不同答 | ✅ |
| 数字准确性 | ❌ 易幻觉 | ✅ 直接查库 |
| 额外成本 | API key + 计费 | 0 |
| 答辩可讲原理 | "调了个接口" | 意图识别 + 槽位提取 + 参数化查询 |
| 闲聊能力 | ✅ | ❌ 不支持 |

**结构**

```
用户输入 → 意图分类（关键词/正则）→ 槽位提取（书名/证号）
        → 参数化查询（MyBatis）→ 模板化回答
```

**支持的意图**

| 意图 | 示例问法 | 回答来源 |
|---|---|---|
| 库存查询 | 「深入理解计算机系统还有几本？」 | `book.stock / total_stock / location` |
| 可借书目 | 「有什么可以借的书？」 | `WHERE stock > 0` |
| 我的借阅 | 「我借了几本书？」 | `borrow_record WHERE user_id` |
| 逾期查询 | 「我有书逾期了吗？」 | `due_date < today AND status=1` |
| 罚金查询 | 「我欠多少钱？」 | `fine_record WHERE status=1` |
| 借阅规则 | 「能借多久？」 | 静态规则文本 |
| 热门推荐 | 「什么书最受欢迎？」 | `ORDER BY borrow_count DESC` |

**形态**：右下角浮动按钮 → 右侧抽屉对话（不占主界面）。

**边界声明**：仅支持上表结构化问题，不支持自由闲聊。这是设计取舍，不是缺陷。

## 5. 技术取舍（四处真实分歧）

### 分歧 1：全站大屏 vs 分角色形态

- **主张**：不把后台整体做成数据大屏
- **理由**：馆员每天要办数十次借还，需要的是短路径操作，不是看实时数字；参考项目 `itcoderyhl/book-manage-server` 也是"管理员首页统计、图书管理仍是表格"
- **结论**：管理员用大屏（展示），馆员用工作台（操作），读者用找书页（检索）

### 分歧 2：AI 接大模型 vs 本地规则

- **主张**：本地规则
- **理由**：断网可用、结果可复现、数字准确、零成本、可讲原理
- **代价**：不支持自由闲聊
- **结论**：如果明确要求"像 ChatGPT 一样聊"，则需接受断网风险与不可复现

### 分歧 3：自助借书 全自助 vs 半自助

- **主张**：半自助（读者可下单，保留柜台核验）
- **理由**：真实图书馆即使有自助机也保留柜台（异常处理、新生办证、老年读者）；本系统无 RFID 硬件，对标的是"线上自助+到馆取书"
- **结论**：读者可自助借，但界面明确提示取书位置与柜台核验

### 分歧 4：封面必须有降级

- **主张**：必须做自动生成封面
- **理由**：`cover` 字段 6 本全为 NULL；只做"有图显示图"等于没做
- **结论**：三层降级（有图 → 自动生成 → 加载失败再生成）
